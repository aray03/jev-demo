Why this exists

The problem with LLMs

Prompt

Is this email a refund request? Answer only "yes" or "no".
"My order showed up smashed. Can I get my money back?"

LLM reply

"Yes, you are absolutely right! This appears to be a refund request. The customer reports their order arrived damaged and is asking for their money back."

if reply == "yes":
    issue_refund()

✗ Never runs. The reply is a whole sentence, not "yes".

  • You have to parse free text
  • No real confidence score
  • Slow, and every output word costs money

Illustrative example of a common failure mode.

Ask for "yes or no" and you often get a paragraph. You end up writing fragile parsing code, and you still don't know how sure the model is.
The basics

What is Jev?

  • The first public System One model, made by TypeSafe
  • You send state (text, JSON, images) and a typed question
  • You get back a typed answer with calibrated probabilities
  • It doesn't write replies, code, or explanations. It judges.

The big difference

System One vs System Two

Jev: System One

  • Fast, intuitive judgments
  • Typed output: Choice, Noul, Score, Box
  • Calibrated probabilities on every answer
  • No free text, so no answer to parse
  • Pay for input only. Output is free.

Claude / ChatGPT: System Two

  • Slow, deliberate reasoning and generation
  • Free-form text you have to parse
  • Can sound confident while being wrong
  • Great for writing, coding, and multi-step plans
  • Output tokens cost 5× input tokens

The names come from Kahneman's Thinking, Fast and Slow: System 1 is quick intuition, System 2 is slow, careful thought.

They aren't competitors so much as different tools. An LLM is a reasoning engine; Jev is the quick gut-check you'd want to call thousands of times a second.

How you ask

Four question types

Choice

Pick one option from a list.

"Which department should get this email?" → billing 0.81

Noul

Probability a statement is true.

"The customer is frustrated." → 0.92

Score

A position on levels you describe.

"How harsh is this review?" → 3.4 (on 0–4)

Box

Where something is in an image.

"Where is the coffee mug?" → x, y, w, h

Try them yourself: console.typesafe.ai/playground

Noul is TypeSafe's name for a probabilistic boolean. Each question is answered on its own, and you can send many in one request that share the same state.

How to build with it

Judgments from Jev,
decisions in code

Jev
"Is the customer frustrated?"
"Is it about a refund?"
→
Your code
a truth table / if-statements
→
Action
escalate · auto-reply · ignore
  • Don't ask "Should we escalate?" Ask the small judgments the decision depends on.
  • Rule of thumb: above 0.7 means yes, below 0.3 means no, and in between means unsure.
Keeps the logic visible and testable. Jev supplies inputs; code owns the decision.
